## 구현된 동작

v0.1.6은 팝오버의 630pt 고정 상한을 제거했다. 같은 SwiftUI 화면을 NSHostingController의 `sizeThatFits`로 측정해 내용에 맞는 높이를 적용한다. 현재 모니터의 사용 가능 높이를 넘으면 카드·헤더·하단의 여백을 줄여 다시 측정하며 글자 크기나 36pt 버튼 높이는 줄이지 않는다. 계정 선택·등록·조회 게시 시 크기를 다시 맞춘다. 내용이 맞으면 세로 ScrollView 자체를 사용하지 않는다. 극단적으로 많은 계정이나 작은 모니터에서 줄인 여백으로도 물리적 높이를 초과할 때만 스크롤을 안전장치로 사용한다.

현재 실계정 5개와 Edu 월간 크레딧, 마지막 계정 및 하단 5개 버튼이 네이티브 화면에 한 번에 표시되는 것을 확인했다. Edu 상세 탭에서도 5시간/주간/월간 한도·확인 시각·누적 토큰·일별 그래프와 버튼 전체가 표시됐으며 세로 스크롤 영역이 없었다. 탭 변경 후 자동 높이 조정도 확인했다. 이 변경은 화면 배치이며 자동 검사를 추가하지 않고 release 빌드와 실제 네이티브 렌더링으로 검증했다.

최종 v0.1.6을 기본 모드로 재실행한 뒤 실제 NSStatusItem의 NSPopover도 접근성 트리와 화면 캡처로 확인했다. 5계정, Edu 월간 행과 하단 버튼이 전부 표시됐고 세로 스크롤 영역이 없었다.

v0.1.5는 Edu/education 계정의 개인 월간 크레딧 한도를 전체 카드와 상세 화면에 추가한다. CLI 0.147.0의 Edu `individualLimit`은 null이었고, 참고 앱이 사용한 `https://chatgpt.com/backend-api/accounts/{workspace}/spend-controls/current-user/monthly-usage` GET에서 HTTP 200과 한도 7,000 / 사용 2107.612383723259를 확인했다. 스크린샷의 약 2,108 사용 / 70% 남음과 일치한다. 이 경로는 참고 앱의 구현과 현재 실계정 응답으로 확인한 비공개 웹 API이며 공식 공개 API 계약으로 보장되는 경로는 아니다.

일반 한도 조회 후 인증 홈의 주체·워크스페이스 일치를 다시 확인하여 해당 Edu 계정 토큰으로만 조회한다. 토큰은 메모리에만 읽으며 출력하지 않는다. 기본 홈·브라우저 쿠키·다른 계정의 인증 정보를 사용하지 않는다. GET의 대상은 고정된 ChatGPT 주소이며 리다이렉트를 거부한다. 한도·사용량의 유효 숫자와 크레딧 단위 및 활성 한도 정책을 검증한다. 누락 값을 0으로 대체하지 않는다. 소수 원본을 저장하고 화면 숫자는 정수로 반올림한다. 비율만 0~100 범위로 제한해 초과 사용량 자체는 보존한다. 리셋 날짜는 해당 응답에 없어 표시하지 않는다.

월간 조회의 실패는 성공한 일반 한도/활동을 가리지 않고 마지막 월간 값과 확인 시각을 유지한다. 기존 동시 조회·취소·요청 revision·계정 UUID 검사를 월간 조회에도 적용하며 재인증/제거된 계정의 늦은 값을 반영하지 않는다. 기존 저장 파일에 월간 필드가 없어도 복원한다.

v0.1.5 자동 검사 18개 통과(등록 19개 중 옵션 실제 CLI 검사 1개 건너뜀). 월간 소수 사용량·0·초과량·null/boolean/NaN/잘못된 단위·비활성 정책, 기존 파일 복원, Edu와 주체/워크스페이스가 일치하는 요청만 허용하는 동작을 검사했다. 설치 앱의 실제 월간 GET 성공 값이 저장되고, 5계정 전체 카드 중 Edu에만 월간 행이 표시되는 것을 확인했다. Edu 상세의 7,000 한도 / 2,108 사용 / 70% 남음과 파란 미터도 네이티브 화면에서 확인했다. 확인용 창은 닫았고 메뉴 막대 앱은 실행 중이다.

v0.1.4는 서버의 `base_model_inference` bucket / `gpt-reserve` 항목과 남은 크레딧·사용 가능한 리셋 크레딧 행을 숨긴다. reserve 항목은 Spark 표시 설정을 켜도 나타나지 않는다. 원본 스냅샷 값은 보존한다. `gpt-reserve`의 정확한 상품상 의미는 공식 문서에서 확인되지 않았으며 reserve라는 이름으로 용도를 추정해 표시하지 않는다.

v0.1.4 기본 자동 검사 15개 통과(실제 CLI 옵션 검사 1개는 건너뜀). 사용자의 진행 중인 로그인 완료를 확인한 후 종료·재실행했다. 실제 등록된 5계정의 전체 카드와 reserve 항목이 있던 계정의 상세를 네이티브 창에서 확인했으며, reserve 및 크레딧 행은 숨겨지고 일반 주간 한도와 활동 집계는 표시됐다. 확인용 창을 닫아 메뉴 막대 앱을 유지했다.

v0.1.3은 `GPT-5.3-Codex-Spark 사용량 표시` 설정을 추가했다. 기본값은 꺼짐이며 이전 설정 파일에 필드가 없어도 숨김으로 복원한다. 서버 bucket `codex_bengalfox` 또는 Spark 표시 이름으로 식별하며 전체 카드·계정 상세의 표시만 필터링한다. 원본 사용량·리셋 날짜와 계정 상태 데이터는 보존한다. 변경은 즉시 저장된다.

v0.1.2의 팝오버 하단은 13pt 글자와 최소 36pt 높이의 버튼 5개를 2행으로 배치한다. 계정 추가는 보라색 강조 버튼, 계정 관리·서비스 상태·설정·종료는 테두리와 배경이 있는 버튼이다. 아이콘, 마우스 호버/누름 상태를 제공하고 `설정…` 표기는 `설정`으로 바꿨다.

Codex CLI의 `account/login/start`로 독립 홈에 로그인한다. 로그인 완료 후 주체·워크스페이스·이메일·플랜을 확인해 등록한다. 재인증은 임시 홈에서 같은 주체와 워크스페이스인지 비교하며 다른 계정으로 교체하지 않는다. 동일 계정을 중복 등록하지 않는다. 이메일을 계정 식별 키로 사용하지 않는다.

한도는 `account/rateLimits/read`, 토큰 집계는 `account/usage/read`를 사용한다. 인증은 앱의 file 저장 모드이며 기본 `~/.codex`를 가져오거나 덮어쓰지 않는다. 한도 성공 값을 먼저 게시하고 선택적 활동 조회 실패는 한도 값을 가리지 않는다. 이전 활동 값은 조회 시각과 함께 유지한다.

전체 탭에서 계정을 비교하고 계정 상세에서 실제 창 길이, 사용/남은 비율과 절대 리셋 시각을 확인한다. 추가 bucket은 Spark 설정과 reserve 숨김 정책을 적용해 표시한다. 크레딧·리셋 크레딧 개수는 조회 데이터에 보존하지만 화면에서 숨긴다. 제공되지 않는 필드는 0으로 계산하지 않는다. 계정 간 퍼센트/토큰 합산, 리셋 크레딧 소비, 작업 실행, 메시지 발송은 하지 않는다.

기본 자동 갱신은 5분이며 실패 재시도 간격은 1→2→4→8→15분까지 늘린다. 사용자가 직접 새로고침하면 기다리지 않고 재시도한다. 인증 실패는 자동 반복을 중단한다. 늦은 응답은 요청 revision과 계정 UUID를 확인해 폐기한다. 재인증 연결 교체 시 새 UUID 홈을 사용해 이전 조회 결과가 새 연결에 게시되지 않는다.

## 검증

v0.1.1에서 실제 CLI 경로를 지정한 `CODEX_USAGE_CONTRACT_CLI="$HOME/.local/bin/codex" ./Scripts/test.sh`의 15개 검사 / 2개 suite가 통과했다. v0.1.3의 `./Scripts/test.sh`는 Spark 설정 검사를 포함한 15개 검사가 통과했으며, 등록된 총 16개 중 실제 CLI 규격 검사 1개는 환경 변수 미지정으로 건너뛰었다.

- 다중 bucket의 우선 해석, 기본/추가 창, 실제 창 길이, Unix 초 시각
- 0/100/null/범위 밖 값과 boolean 오인 방지
- 이전 설정 파일의 누락 필드 기본값과 잘못된 갱신 간격 복구
- Spark 기본 숨김·bucket/이름 식별·다른 한도 유지·원본 보존·표시 설정 저장/복원
- 누적 토큰 미제공과 0의 구분
- 리셋 시간이 지나도 기존 사용률을 임의로 0으로 바꾸지 않음
- 같은 이메일의 다른 주체/워크스페이스 구분과 이메일 불일치 거부
- 계정/스냅샷 저장 복원, 인증 파일 0600, 한 홈 제거 시 다른 홈 보존
- symlink 홈 삭제 거부
- stdio 초기화, 불필요한 알림 건너뛰기, 로그인 완료 알림
- stderr 대량 출력 중 정상 응답 수신
- 시간 제한, 취소와 자식 조기 종료 오류
- 두 RPC 클라이언트의 서로 다른 홈 환경 유지
- 로그인 완료 알림 이후 계정 정보 확인까지 필수 `account/read.params` 검사
- 실제 CLI 0.147.0의 빈 임시 홈에서 누락 `params`의 -32600 재현과 수정한 계정 정보 요청의 정상 처리 확인. 실제 인증 정보나 원격 사용량은 사용하지 않음

`./Scripts/build.sh`로 release 실행 파일·아이콘·앱·ZIP을 생성했다. 설치된 앱의 `codesign --verify --deep --strict`가 `valid on disk` / `satisfies its Designated Requirement`로 완료됐다. 링크된 라이브러리는 시스템 프레임워크와 Swift 런타임이며 빌드 폴더나 Xcode 테스트 라이브러리에 의존하지 않는다.

네이티브 샘플 모드에서 실제 NSPopover의 4계정 전체 보기, 정상/한도 도달 상태, 계정 탭 전환, 5시간·주간 사용률과 남은 비율, 절대 리셋 날짜를 화면으로 확인했다. 설정 창의 4계정 표시와 남은 비율 설정 변경도 확인했다. 팝오버의 전체 목록은 스크롤하며 메뉴 막대 숫자 표시는 설정에서 켠다. 이 샘플 모드는 실제 계정 저장소/로그인/네트워크 조회를 사용하지 않는다.

기본 실행 모드에서 CLI 자동 발견과 빈 계정 설정 화면, 계정 추가 버튼으로 열리는 별칭 입력/로그인 창도 확인했다. 실제 로그인 버튼은 누르지 않았으며 사용자 계정의 인증 정보를 읽거나 가져오지 않았다.

v0.1.2 하단 디자인은 기본 모드 팝오버의 접근성 트리와, 동일한 `UsagePopover`를 호스팅한 네이티브 확인용 창(`--preview-window`)의 실제 화면으로 검증했다. 4계정 샘플의 스크롤 영역과 하단 5개 버튼, 기본 모드의 활성 보라색 계정 추가 버튼에 텍스트 잘림이 없었다. 계정 관리 버튼 클릭 후 설정 창이 열리는 것을 확인했다. 팝오버 직접 화면 캡처는 간헐적으로 창 없음/타임아웃이 발생해 확인용 창을 사용했다. 이 플래그는 기본 실행에는 영향을 주지 않는다.

## 현재 제한과 다음 검증

v0.1.0은 로그인 완료 후 `account/read`의 필수 `params`를 누락해 `Invalid request: missing field params`(-32600) 오류가 발생했다. v0.1.1은 공식 App Server 예제와 로컬 스키마에 맞춰 `params: {"refreshToken": false}`를 보낸다. 로그인 후 검증과 정기 조회가 같은 수정 경로를 사용한다. 이전 버전은 실패한 임시 로그인 홈을 정리했으므로 등록되지 않은 계정은 다시 로그인해야 한다. 이미 등록된 계정 저장소는 빌드·교체 시 수정하지 않는다.

사용자가 앱에서 5개 실계정을 등록한 후 전체 화면의 한도와 상태, 특정 계정의 상세 사용량·활동 집계가 표시되는 것을 확인했다. OAuth 승인은 사용자가 진행했다. 토큰 장기 갱신과 웹 대시보드의 값 대조, 다른 네트워크·관리 정책의 호환성은 아직 검증하지 않았다. CLI 0.147.0이 생성한 로컬 RPC 스키마와 공식 문서를 기준으로 구현했다.

다중 워크스페이스 선택 UI는 제공하지 않으며 로그인된 워크스페이스를 고정한다. 한도 리셋을 지나면 `리셋 확인 중`으로 표시하지만 서버 값의 비정상적인 조기 감소를 별도 후보로 보류하는 정책은 아직 구현하지 않았다. 알림, 장기 사용률 이력, 서비스 장애 피드, 자동 업데이트도 후속 범위이다. 서비스 상태는 OpenAI 상태 페이지 링크로 제공한다.

macOS 14/15의 다른 기기, Intel, 로그인 항목 권한 승인, 실제 잠자기 복귀와 배터리/메모리 측정은 추가 검증 대상이다. 이번 검사 결과를 실계정 E2E 또는 다른 Mac의 배포 검증으로 해석하지 않는다.
